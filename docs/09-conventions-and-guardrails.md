# 09 — Conventions & Guardrails

## Do NOT change casually

| Area | Why |
| --- | --- |
| `src/routeTree.gen.ts` | Generated by the router plugin from `src/routes/`. |
| `src/integrations/supabase/client.ts`, `client.server.ts`, `auth-middleware.ts`, `auth-attacher.ts`, `types.ts` | Auto-generated Cloud integration files. Regenerate, never hand-edit. |
| `.env`, `supabase/config.toml` | Managed by the platform. |
| `src/lib/i18n.ts` language detection | The detector is intentionally absent — re-adding it reintroduces hydration mismatches. Arabic must be the first render on both server and client. |
| `src/styles.css` tokens | Single source of truth for the design system. Components must use semantic tokens, never `text-white` / `bg-[#...]`. |
| RLS policies & the `has_role` function | Every table's authorization depends on them. Roles live only in `user_roles` — never on a profile/user row. |
| `uploadPassport` path generation | The storage path must stay server-generated; letting the client choose it would allow overwriting other bookings' files. |
| `enforceRateLimit` on public writes | Removing it exposes anonymous endpoints to abuse. |
| Public write path | Anonymous writes must go through server functions (validate + sanitize + rate limit). Do not add anon INSERT policies or write to tables from the browser as an anonymous visitor. |
| Booking form field set | Passport number, nationality, DOB, expiry and emergency contact were deliberately removed. Do not reintroduce them. |
| `BranchesSection` reuse | `/admin/branches` and Settings → Branches share one component on purpose. |
| Admin `ssr: false` | The dashboard depends on the browser Supabase session. |
| `/mcp` routes and `.well-known` | Part of the agent integration contract. |
| `/.well-known/trust.html` / `trust.json` | Platform-reserved. Never create, proxy, or imitate. |

## Where to add things

| Task | Location |
| --- | --- |
| New public page | `src/routes/<name>.tsx` with its own `head()` (unique title/description/OG) |
| New public read | a new query factory in `src/lib/queries.ts` |
| New anonymous write | new `createServerFn` in `src/lib/*.functions.ts` + zod schema in `*.schema.ts` + `enforceRateLimit` + sanitizers |
| New admin screen | `src/routes/admin.<name>.tsx`, register the nav entry in `AdminShell`, build with `src/components/admin/kit` |
| New privileged aggregate/report | loader in `src/lib/admin/*.server.ts`, exposed by a `createServerFn` in `command.functions.ts` with `requireSupabaseAuth` + `assertAdmin` |
| New setting | add a `SettingSpec` to the relevant section and let `useSiteSettings` persist it in `site_settings` (choose the right `group`) |
| New content type | migration (table + GRANTs + RLS + `updated_at` trigger) → query factory → public component → admin CRUD screen → locale keys |
| New translatable field | see `08-i18n.md` ("Adding a new translatable field") |
| New email | render helper in a `*-email.server.ts`, called from the server function; Resend via `fetch` |

## Coding conventions observed in the repo

- **Server functions**: `createServerFn({ method })` → `.middleware([...])` →
  `.inputValidator(zod)` → `.handler()`. Module scope of `*.functions.ts` files
  stays thin (imports + exported declarations only); server-only helpers and
  `supabaseAdmin` are `await import()`-ed inside handlers.
- **`process.env`** is read inside handlers, with bracket notation.
- **Queries**: option factories + explicit query keys; mutations invalidate the
  matching keys (`["site_settings"]`, `["admin-notifications"]`, …).
- **Components**: no exported route components (keeps code splitting working); no
  module-scope statements referencing route components.
- **Toasts**: `sonner` (`toast`, `@/components/ui/sonner`) — `@/hooks/use-toast`
  does not exist here.
- **Icons**: `lucide-react`, dynamic names through `DynamicIcon`.
- **Direction-safe utilities** (`ms-`, `me-`, `ps-`, `pe-`) instead of left/right.
- **Never** add `react-router-dom`, `src/pages/`, or `src/App.tsx`.

## Known limitations summary

1. Public site is request-based with a 5-minute stale window — no realtime push.
2. No sitemap route and no canonical tags.
3. `notify_*` settings are stored but unused (`NOT CONNECTED`).
4. Email recipient comes from env, not from Settings → Email.
5. Owner emails are best-effort; failures only log.
6. Rate limiting fails open on infrastructure errors.
7. Main-branch exclusivity is app-level, not a DB constraint.
8. `staff` role exists in types but has no RLS access.
9. Smart Insight strings are single-language.
10. Many `_en` (and some `_fr`) content columns are still `NULL`.
11. `site_settings` is world-readable — never store secrets there.
12. Admin CRUD writes rely solely on RLS (no server-side validation layer).
